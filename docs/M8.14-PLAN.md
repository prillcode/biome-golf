# M8.14 Plan — Decked Driver Rollout

## Goal

Make a Standard Driver shot from the deck behave like a low runner after landing, while
preserving the server-authoritative launch penalty and leaving explicitly selected Stinger
behavior intact.

## Decision

The ball model's `rollingFrictionMultiplier` multiplies surface rolling retention; lower
values brake faster. Stinger's rollout comes primarily from its higher landing retention
(`0.60` versus lofted Standard's `0.25`), while its `0.65` rolling multiplier brakes the
subsequent run faster. Therefore decked Standard Driver shots use an intermediate `0.40`
landing retention and keep Standard's existing rolling-friction multiplier: enough extra
run without copying Stinger's full landing retention. Deck launch scaling and accuracy
penalty remain unchanged. Decked Stinger remains unchanged.

Club carry values are in blocks; the HUD's yard display applies the existing 1.75
conversion.

## Scope

- Increase landing retention only for Standard Driver shots from the deck.
- Keep tee Driver, all other clubs, decked Stinger, shot counting, and lie classification
  unchanged.
- Add a deterministic flight regression proving the decked Standard Driver rolls farther
  than its previous decked profile while remaining shorter than a teed Driver.
- Update milestone status and changelog.

## Verification

Run unit tests, Gradle build, Loom client/server boot, Docker sync/restart/health and JAR
identity, then stage the exact artifact in both local clients. Manual client/flight
acceptance is recorded separately if a client cannot be safely restarted during this task.
