# M8.8 - Distance Display Units

**Status:** In progress. The user explicitly authorized M8.8 as an independent
presentation slice before M8.7 closeout; M8.7 remains planned and its scope is unchanged.

M8.8 adds golf-style yard display while preserving blocks as the authoritative internal
unit for gameplay, networking, physics, scoring, and course geometry.

It also exposes server-authoritative cumulative horizontal travel for the current shot so
players can see the shot distance while the ball is moving and after it comes to rest.

## Purpose

Display familiar golf distances in yards using the fixed presentation conversion:

```text
1 block = 1.75 yards
```

Displayed values are rounded to the nearest whole unit. The conversion is presentation
only and does not change any gameplay distance or tuning value.

## User Experience

- Default display unit is **Yards**.
- Configurable keybind `Y` toggles between **Yards** and **Blocks**.
- The client briefly reports the selected unit after toggling, for example:
  - `Distance units: Yards`
  - `Distance units: Blocks`
- The preference is client-local presentation state and is not server gameplay state.
- The keybind is registered through the existing Minecraft Golf controls category and is
  rebindable through Minecraft's Controls screen.

## Displayed Club Distances

| Club | Internal blocks | Display yards |
|---|---:|---:|
| Driver | 150 | 263 |
| Fairway Wood | 125 | 219 |
| Long Iron | 100 | 175 |
| Mid Iron | 85 | 149 |
| Short Iron | 60 | 105 |
| Wedge | 42 | 74 |
| Putter | 22 | 39 range/roll |

The putter value should be labeled as range or roll distance rather than airborne carry.

## Scope

### Swing HUD

Convert the selected club's nominal display distance. For example:

```text
~263 yards
~150 blocks
```

The underlying `ClubDefinition.nominalCarry()` value remains in blocks.

### Hole HUD

Convert the authoritative cup distance currently displayed in blocks. For example:

```text
Cup: ^ 88 yards
Cup: ^ 50 blocks
```

The server continues to calculate and transmit the cup distance in blocks.

### Shot Travel HUD

The Hole HUD displays the cumulative horizontal distance traveled by the current shot:

```text
Shot: 150 yards
```

The server accumulates movement in blocks from each authoritative physics segment. Flight
height is not added to the measurement. The counter resets when a new shot launches or
the ball is repositioned for tee/recovery state.

## Server-First Boundary

- `HoleStatePayload.distanceToCupBlocks` remains the canonical network field.
- Physics, club tuning, collision, scoring, tap-in rules, and course geometry remain
  block-based.
- The server does not trust, store, or use the client's selected display unit.
- The enhanced Java client converts canonical block values only when rendering UI.
- A future Bedrock or Geyser-compatible presentation can apply the same conversion to
  the canonical block value independently.
- Vanilla-compatible server messages continue using blocks unless a later milestone
  explicitly adds a server-side display projection.

## Technical Direction

Add a small platform-neutral distance conversion/formatting utility so the factor and
rounding rule are not duplicated across HUD code:

```java
yards = Math.round(blocks * 1.75)
```

Keep unit preference and `Y` key handling in the client input layer. No network payload
version change is expected.

Whether the local display preference persists across client restarts is out of scope for
this milestone; initialize to Yards unless a persistence requirement is added before
implementation.

## Bounded Slices

Each slice must pass its verification before the next begins. Stop and document any
required deviation from `docs/ARCHITECTURE.md`.

### S0 - Baseline and Conversion Contract

- Record the current test/build and installed-client baseline.
- Define the fixed `1.75` conversion and whole-unit rounding behavior.
- Add plain-Java tests for representative club distances and rounding boundaries.
- Confirm the server payload and gameplay values remain block-based.

### S1 - Client Unit Preference and Keybind

- Add the configurable `Y` keybind to the existing Golf controls category.
- Add client-local Yards/Blocks display state, defaulting to Yards.
- Toggle the state without sending a gameplay packet or mutating server state.
- Provide brief visible feedback after a successful toggle.

### S2 - HUD Integration

- Update the Swing HUD's club distance display.
- Update the Hole HUD's cup-distance display.
- Add the Hole HUD's server-authoritative current-shot travel display.
- Keep labels explicit so the active unit is always understandable.
- Preserve the existing HUD layout on desktop and narrow client resolutions.
- Label putter distance as range/roll rather than carry where appropriate.

### S3 - Integrated Verification and Closeout

- Verify both HUDs in Yards mode and Blocks mode.
- Verify the keybind appears in Controls and can be rebound.
- Verify solo and Ready Golf snapshots still render correctly.
- Verify no serverbound unit preference or client-authored distance is introduced.
- Record final artifact, tests, and any presentation limitations in

## Non-Goals

- Changing gameplay distance or club tuning values.
- Converting physics, scoring, course bounds, or server calculations to yards.
- Adding server configuration for units.
- Adding meters, feet, or other alternate unit systems.
- Implementing Bedrock/Geyser compatibility.
- Migrating course data or network payloads from blocks to yards.
- Persisting the local display-unit preference across client restarts.

## Exit Criteria

M8.8 is complete when:

1. The Swing HUD displays all club distances in yards by default using the `1.75`
   multiplier.
2. The Hole HUD displays authoritative cup distance in yards by default.
3. The Hole HUD displays current-shot travel while the ball is moving and after natural rest.
4. `Y` toggles all distance displays between yards and blocks and is rebindable.
5. Displayed yard values round consistently and match the documented club table.
6. Server payloads, gameplay calculations, and authoritative state remain block-based.
7. Solo and Ready Golf clients receive and render the same authoritative distance values.
8. Automated, Loom, Docker, installed-client, and manual HUD verification passes.
9. `docs/M8.8-CLOSEOUT.md` records the final conversion behavior and verification.
