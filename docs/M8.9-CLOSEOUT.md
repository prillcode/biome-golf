# M8.9 - Practice Range: Closeout

**Status:** Complete.

M8.9 promotes the operator-authored practice range - built alongside M8.8 - to its own
documented, server-authoritative slice. M8.8 is client presentation; M8.9 is an operator
authoring and world-persistence feature. It was committed separately from M8.8 so the
presentation milestone's scope stays clean.

## Delivered

- `PracticeRangeService` is a world-scoped singleton registered on server start/stop. It
  loads and saves `data/minecraft_golf_practice_range.json` on the server's
  `LevelResource.ROOT` path and fails closed on malformed files.
- `/golf practice tee set` records the operator's standing position as the practice tee;
  `/golf practice tee` teleports back when the dimension matches.
- `/golf practice target set <1-8>` places a golf cup and flag at the operator's standing
  position and records it; moving a target clears the previous cup/flag marker.
- `/golf practice target clear <1-8>` removes the recorded cup/flag markers and forgets
  the target.
- `/golf practice target list` prints the saved tee and targets 1-8.
- Existing `/golf practice ball` and `/golf practice clear` are unchanged.
- `GolfCourseCommands.placeFlag` / `clearMarker` were widened from `private` to
  package-private so the practice range reuses the course marker helpers instead of
  duplicating them.
- `PracticeRangeService.isValidTargetNumber` is the single `1..MAX_TARGETS` bound rule,
  shared by command input, persistence loading, and `PracticeRangeServiceTest`.

## Server-First Boundary

- The server owns the practice tee, targets, and persistence; there is no network payload
  or client-authored practice state.
- Target numbers are bounded to 1-8 and `PracticeRangeServiceTest` pins the boundary.
- Cross-dimension teleport and marker placement/removal are rejected with a failure
  message rather than applied in the wrong dimension.
- No scoring, round, or hole state is affected.

## Manual Verification

Automated, Loom, Docker, and RCON-persistence verification pass, and the existing dev
world already carries six authored targets. The remaining boundary is in-game command
use by a player (the RCON console has no player for `tee set`, `tee`, or `target set`,
which require a standing player). The recommended confirmation pass:

- `/golf practice tee set` then `/golf practice tee` returns the player to the tee.
- `/golf practice target set 8` places a cup and flag and updates `target list`.
- `/golf practice target clear 8` removes the markers and forgets the target.
- A ball struck from the practice tee reports shot travel on the Hole HUD (M8.8).

## Deferred

- Practice scoring, handicaps, and leaderboards remain out of scope.
- Automatic target placement or terrain shaping remains out of scope.
- A player-facing (non-operator) practice-range setup flow is not part of M8.9.
