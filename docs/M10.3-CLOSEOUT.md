# M10.3 — Tier 1 Closeout and Bedrock Re-Shelve Decision

**Date:** 2026-09
**Status:** Closed. M10.3 Tier 1 shipped, then the client-light/Bedrock track was shelved again
in favour of the Java experience.

## Decision

Development returns to the **Java experience** (the supported product). Bedrock via Geyser is
unmaintained as a *play* client. The client-light code built under M10/M10.3 stays in the tree —
every path is gated on `!canSend(HoleStatePayload)` and costs the modded Java client nothing —
but no further Bedrock *play* work is planned and no Bedrock play acceptance is claimed.

**Follow-up (2026-09):** rather than dropping Bedrock entirely, client-light connections were
repurposed as a promotional **visitor mode** — they watch (spectator or adventure) and are
invited to join on Java. See `docs/BEDROCK-VISITOR-MODE-PLAN.md`. The play paths remain dormant.

## What shipped

**M10.3 Tier 1 (commit `9e0f7b5`):**

- **S1 ball mirror gate.** `GolfBallEntity.tickVisual` spawns the vanilla snowball proxy only
  while a client-light player is online, in the same dimension, and within tracking range; the
  normal all-modded-Java world shows only the custom ball.
- **S2 no server camera.** The `BallCameraService.followShot(...)` call was removed from
  `ShotService.attempt`; the class stays dormant.
- **S3 vanilla presentation fallbacks.** `ClientLightPresentation` mirrors authoritative
  snapshots into the action bar and the final scorecard into chat; `HeldShotService` shows a
  charge boss bar. No payload shape, `HoleStateNetworking`, or modded HUD changed.
- **S4 hole visibility** via the action-bar distance readout; no different blocks placed.

**G1 tap-meter input (commit `c2c376d`):**

- Replaced the hold-based input after the playtest showed Geyser never delivered a release.
  Each use tap advances a power step (25/50/75/100%), firing after a 15-tick window or on the
  4th tap, with a per-player boss bar and a one-time hint. Unverified on a real Bedrock client.

## Why it was re-shelved

The 2026-09 Bedrock playtest (logged in `docs/BEDROCK-GUEST-MODE-PLAN.md`) showed the remaining
problems are **feel**, not visuals:

- held-use always auto-fired at `power=1.0 after 200 ticks` — the server never observed a
  release event from Geyser;
- ball flight was choppy, with the dev server at times 50–86 ticks behind;
- Geyser logged repeated packet-translation errors and custom-block chunk errors.

A resource pack fixes looks, not feel. The strategic call, consistent with the project priority
order (`good golf > maintainable server > Java experience > client-light > Bedrock`), is to stop
investing in the lowest-priority client and put the effort into Java.

## Verification performed

- `./gradlew test` / `./gradlew build`: 333 tests, all passing, at both M10.3 Tier 1 and the G1
  tap-meter change.
- Docker dev server synced and restarted with the Geyser overlay; container healthy; host and
  container JAR hashes matched.
- No Java regression: no `net.minecraft.client` imports in `src/main`; core packages remain
  Minecraft-free; modded HUD, camera, payloads, and blocks unchanged.
- **Not verified:** a real Bedrock two-client round (manual, not pursued).

## What stays dormant

All of the following remain in the tree, gated and unsupported:

- `server/HeldShotService` + `club/HeldShotRules` (tap meter),
- `server/BallCameraService` (dormant; no caller),
- `server/ClientLightPresentation`, `hole/ClientLightHudText`, `net/RoundScorecardText`,
- the `GolfBallEntity` vanilla mirror path,
- the dual-club fallback in `GolfItems` and the optional-registry connection fix,
- the `dev-server/docker-compose.geyser.yml` overlay and `scripts/dev-server-geyser-up.sh`.

## If Bedrock is ever resurrected

Start from the decision record, not the code: read `docs/BEDROCK-GUEST-MODE-PLAN.md`,
`docs/BEDROCK-NATIVE-ADDON-RESEARCH.md`, and the Tier 2 research, then choose a direction and
plan it as a fresh track. Re-verify the pinned Geyser build against the current MC version
first — the 2026-09 logs showed translation errors on the pinned combination.

## Next focus

The **Java experience**. M0–M8.10 are complete; M9 (additional game modes) remains deferred.
