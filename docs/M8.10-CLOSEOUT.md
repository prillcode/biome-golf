# M8.10 - Course Landscape Protection: Closeout

**Status:** Complete. Automated, Loom, Docker/RCON, and the in-game operator/non-operator
break/place/TNT matrix all pass; the operator confirmed the manual matrix below.

M8.10 adds an operator-authored whole-course landscape perimeter that blocks block break,
block place, and TNT detonation inside it, plus a per-course lock that removes the
operator exemption. It works for both drafts and finalized courses, keeps hole metadata
immutable, and introduces **no Mixin** (`fabric.mod.json` still has `"mixins": []`).

## Delivered

### S0 - Region and verdict model

- `CourseLandscape(courseId, dimension, bounds, locked)` is the Minecraft-free perimeter:
  an inclusive `HoleBoundary` box plus a lock flag. The id and dimension are normalized
  through the same rules as authored courses.
- `ProtectionVerdict` is `ALLOW` / `DENY_NON_OP` / `DENY_ALL` with `mostRestrictive` and
  `denies(hasOperatorPermission)`.
- `CourseProtection.resolve(zones, landscapes, x, y, z)` combines tee/cup cylinders
  (`DENY_NON_OP`) with landscape perimeters (verdict by lock state), most-restrictive-wins.
  `mayBreak(zones, landscapes, ..., cupBlock, operator)` applies the operator exemption and
  keeps the cup block permanently non-operator protected. The old 5-argument `mayBreak` is
  retained and delegates with an empty landscape list.

### S1 - Store and persistence

- `AuthoredCourseStore` holds a `CourseLandscape` per draft or finalized course.
  `setLandscape` requires the course to exist and enforces `landscape.dimension ==
  course.dimension`; `clearLandscape` returns whether one existed; `landscape(id)` and
  `landscapes()` expose it. `cloneCourse` copies the perimeter (re-keyed to the clone) and
  `removeCourse` drops it. Finalize keeps it (same course id), so a draft perimeter carries
  into the finalized course without touching immutable hole metadata.
- `AuthoredCourseStoreJson` writes an optional per-course `"landscape": {min,max,locked}`
  object and loads an absent field as "no perimeter, unlocked", so existing world files
  stay valid.

### S2 - Break and place guard

- `CourseProtectionIndex` now indexes landscape perimeters by dimension for drafts and
  finalized courses alongside the tee/cup zones, and exposes `verdict` and `tntVerdict`.
- `CourseBlockBreakGuard` evaluates breaks through the verdict model. It also registers
  `BlockEvents.USE_ITEM_ON` and denies a held `BlockItem` placement when the clicked or the
  adjacent placement position is protected.
- Only `BlockItem`s (and TNT in S3) are considered, so doors, buttons, levers, and
  containers keep working inside a perimeter.

### S3 - TNT guard (no Mixin)

- `CourseProtectionConfig` gains `tntBlastSafetyMargin` (default `4.0`, the vanilla TNT
  explosion radius). `CourseLandscape.expandedBy(margin)` and
  `CourseProtection.resolveForTnt(...)` provide the expanded verdict.
- `USE_ITEM_ON` denies placing `Items.TNT` or `Items.TNT_MINECART`, and denies igniting an
  existing `Blocks.TNT` with flint & steel or a fire charge, using the blast-margin-expanded
  verdict for both the clicked and adjacent positions.
- `ServerEntityEvents.ALLOW_LOAD` cancels a newly spawned (`!loadedFromDisk`) `PrimedTnt`
  inside the expanded perimeter. This catches what item checks cannot: TNT placed before
  the perimeter was authored, and redstone/dispenser/fire/flaming-arrow ignition.
- Lock semantics: a locked perimeter (`DENY_ALL`) cancels every new charge. An unlocked
  perimeter (`DENY_NON_OP`) cancels the charge unless the player who primed it is an
  operator (`PrimedTnt#getOwner`), so operators regain TNT via flint & steel / fire charge
  while non-operator and owner-less ignition is still refused. Saved entities are never
  cancelled, so chunk loads cannot delete charges.

### S4 - Commands and feedback

- `/golf course landscape bounds|clear|lock|unlock|status`, all gamemaster-gated.
  `bounds` is a two-corner, player-position capture with a per-player pending corner,
  builds the XZ box and expands Y to build height, preserves the existing lock, and is
  refused while a round/attempt is active and outside the course's dimension.
  `clear` removes the perimeter and lock; `lock`/`unlock` require an existing perimeter;
  `status` prints kind (draft|finalized), dimension, lock state, and bounds.
- Target resolution: the player's current draft, else the active selected course, else
  `[golf] no course selected; use /golf course select <id> or /golf course edit <id>`.
- Every successful mutation saves the world JSON and calls `refreshProtection()` so the
  guard index changes immediately.

## Decisions and deviations

- **`InteractionResult.CONSUME`, not `FAIL` (plan correction).** The plan stated that
  returning `InteractionResult.FAIL` from `BlockEvents.USE_ITEM_ON` cancels the placement.
  That is not true in Minecraft 26.2: the Fabric mixin only substitutes the
  `BlockState#useItemOn` return value, and `ServerPlayerGameMode#useItemOn` checks
  `consumesAction()` (`false` for `FAIL`) before falling through to `ItemStack#useOn`, which
  places the block. This was verified against the game bytecode and with a temporary
  event probe: all-null listeners return `null` (vanilla runs), `FAIL.consumesAction() ==
  false`, `CONSUME.consumesAction() == true`. The guard therefore returns `null` to allow
  and `InteractionResult.CONSUME` to deny. `docs/M8.10-PLAN.md` now records this.
- **Optional `[<id>]` on `clear|lock|unlock|status` (plan extension).** The plan calls the
  unlocked command the intended escape hatch, but a console/RCON source has no player and
  no persisted course selection after a restart. The explicit id makes
  `/golf course landscape unlock <id>` work from console/RCON, which was verified over
  RCON. `bounds` stays player-position based.
- **`ALLOW_LOAD` is owner-aware for unlocked perimeters.** Cancelling every new `PrimedTnt`
  would break "operators regain TNT when unlocked"; cancelling none would let non-operators
  ignite pre-existing TNT with redstone/fire/arrows. The guard cancels unless the igniter is
  an operator, which satisfies both.
- **Perimeters are course-dimension scoped.** `setLandscape` rejects a dimension mismatch so
  protection is always keyed to the world the course is played in.

## Non-goals (unchanged from the plan)

- No Mixin or mixin config; `fabric.mod.json` `"mixins": []` is intact.
- Non-TNT explosions (beds, respawn anchors, end crystals, fireballs, wither skulls,
  creepers) are not guarded.
- Fire spread, pistons, endermen, and other non-break/non-place/non-TNT vectors are not
  guarded. Fluid buckets (water/lava) are block-mutating but are not `BlockItem`s and are
  not guarded.
- A TNT minecart that is pushed into or primed inside a perimeter is not intercepted
  (cancelling `MinecartTNT#primeFuse`/`explode` would require a Mixin). Placing a TNT
  minecart inside the expanded perimeter is denied for non-operators.
- No entity, drop, or player explosion-damage protection; no per-hole granularity; no
  client HUD or network payload changes.
