# M8.13 Closeout — HUD Visibility and Command Help

## Delivered

- Added `H` (`key.minecraft_golf.toggle_swing_hud`) in the `minecraft_golf:controls`
  category. It toggles SwingHud and HoleHud together.
- Added permission-free server `/golf hud`, sending a clientbound toggle intent. The
  receiving client toggles from its current visibility; the state remains client-only,
  in-memory, and resets when the game process restarts.
- Club-in-hand right-click reveals both HUDs before swing handling, including the
  no-resting-ball feedback path.
- `/golf help` now presents the concise player page; `/golf help admin` is discoverable
  to everyone and labelled OP/GAMEMASTER ONLY. Existing server permission gates remain
  unchanged.
- Added a test covering every registered top-level `/golf` literal across the help pages,
  updated the command guide/changelog, and corrected the registration log message.

## Command Routing Regression and Correction

The first client-local implementation registered a partial `/golf` root containing only
`hud`. A player reported B failing with "Incorrect argument for command at position 5:
golf <--[HERE]". Fabric 26.2's client dispatcher intercepts that root and treats sibling
server commands as incorrect arguments instead of forwarding them, explaining why no
server exception appeared. This also affected `/golf help` and other sibling commands.

Removed `HudClientCommands` and its registration entirely. `/golf hud` now lives on the
server tree and sends `ToggleHudPayload` only to clients advertising its receiver. Older
or unmodded clients get update guidance rather than an unsupported packet. H and swing
reveal remain local. Added payload-codec tests and source-boundary checks preventing a
shadow client `/golf` root from returning.
