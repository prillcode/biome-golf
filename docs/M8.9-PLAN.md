# M8.9 - Practice Range

**Status:** Implemented and closed as its own slice. The practice range was built
alongside the M8.8 work but is conceptually separate: M8.8 is client presentation, while
M8.9 is a server-authoritative operator authoring and persistence feature. It is
documented here because it was built outside the M8.8 plan's scope.

## Purpose

Give operators a persistent practice place built on the existing practice-ball mode: a
saved tee to return to and up to eight cup-and-flag targets to aim at. This complements
the M8.8 shot-travel HUD by giving players a repeatable place to measure shots.

## User Experience

- `/golf practice tee set` (gamemaster) records the operator's standing position as the
  practice tee for the current dimension.
- `/golf practice tee` teleports the player to the saved tee when the dimension matches.
- `/golf practice target set <1-8>` (gamemaster) places a golf cup and flag at the
  operator's standing position and records it as target N.
- `/golf practice target clear <1-8>` (gamemaster) removes the recorded target's
  cup/flag markers and forgets it.
- `/golf practice target list` prints the saved tee and every target 1–8.
- Existing `/golf practice ball` and `/golf practice clear` are unchanged.

## Server-First Boundary

- The server is authoritative for the practice tee, targets, and their persistence.
- Target numbers are bounded to `1..8`.
- Cross-dimension teleport and marker placement/removal are rejected rather than applied
  in the wrong dimension.
- Persistence is world-local JSON at `data/minecraft_golf_practice_range.json`.
- No scoring, round, or hole state is affected; practice range is command/operator driven.

## Technical Direction

- `PracticeRangeService` is a world-scoped singleton registered on server start/stop and
  loaded/saved on the server's `LevelResource.ROOT/data` path.
- `GolfHoleCommands` owns the `/golf practice` subtree and reuses the existing
  `GolfCourseCommands.placeFlag` / `clearMarker` helpers, which were widened from private
  to package-private rather than duplicated.
- `PracticeRangeService.isValidTargetNumber` is the single bound rule, shared by command
  input, persistence loading, and the plain-Java test.

## Non-Goals

- Scoring, handicaps, or leaderboards for practice.
- Shared or non-world-scoped practice state.
- Automatic target placement, terrain shaping, or a new distance UI beyond the M8.8
  shot-travel HUD.
- Network payload changes.

## Verification Ladder

```text
plain-Java bound test
        -> ./gradlew test
        -> ./gradlew clean test build
        -> Loom dedicated server
        -> Loom client
        -> Docker sync/restart/health
        -> RCON command and persistence check
        -> installed-client JAR hash
        -> manual in-game command check
        -> M8.9 closeout
```

## Exit Criteria

M8.9 is complete when:

1. Tee set/go and target set/clear/list work through the command tree.
2. Configuration persists across a server restart.
3. Target numbers are bounded and dimension checks prevent cross-dimension edits.
4. Automated, Loom, Docker, RCON, and installed-client checks pass.
5. `docs/M8.9-CLOSEOUT.md` records the verification and the manual boundary.
