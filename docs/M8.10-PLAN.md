# M8.10 - Course Landscape Protection

**Status:** Planned. M8.7-M8.9 are complete; M9 remains deferred. Do not begin
implementation until this plan is explicitly started.

M8.10 adds an operator-authored, whole-course landscape perimeter that prevents players
from destroying the course environment (block break, block place, and TNT detonation)
inside it, plus a per-course lock that removes the operator exemption.

## Purpose

Today only tee/cup vicinity is protected, only for finalized courses, and only against
block breaking. Operators can still strip the fairway, fell the trees, and blow holes in a
finished course. M8.10 protects the whole authored landscape while keeping play possible.

## Current Baseline

- `CourseBlockBreakGuard` (`PlayerBlockBreakEvents.BEFORE`) cancels breaks inside tee/cup
  vicinity cylinders (`CourseProtection`, `ProtectedZone`, radius 12 / half-height 8).
- Placement is unguarded. Explosions are unguarded. Only finalized courses are indexed.
- Operators (permission level `GAMEMASTERS`, 2) are always exempt.
- Finalized courses are immutable: `/golf course edit` refuses them, and hole metadata is
  frozen after finalize.
- The project currently ships no Mixins (`fabric.mod.json` `"mixins": []`), and M8.10 is
  designed to keep it that way.

## Model

### Course landscape metadata

`CourseLandscape` is course-level, mutable metadata keyed by normalized course id and
stored for **both drafts and finalized courses**, so finalized courses can still receive a
perimeter and a lock without re-finalizing or cloning:

```text
CourseLandscape(courseId, dimension, bounds, locked)
```

- `bounds` is the same inclusive axis-aligned box shape already used by hole boundaries
  (`HoleBoundary`, built by `AuthoredHoleBounds.fromCorners`), with Y expanded to the
  world build height. X/Z come from two operator-captured corners.
- `locked` is the operator lock flag (see below).
- Absent metadata means "no perimeter, unlocked" and is fully backward compatible with
  existing world JSON.

Keeping this separate from the immutable `CourseDefinition` avoids weakening finalize
semantics; only the environment protection metadata stays mutable.

### Protection verdict

Every block-mutation query resolves to one of:

- `ALLOW` - outside every protected region.
- `DENY_NON_OP` - protected, but operators may still edit (repair).
- `DENY_ALL` - protected and locked: no player may edit, regardless of permission.

Region rules:

- Existing tee/cup vicinity cylinders: `DENY_NON_OP` (unchanged behavior).
- Landscape perimeter: `DENY_ALL` when `locked`, otherwise `DENY_NON_OP`.
- If a position is inside several regions, the most restrictive verdict wins.

The lock blocks **block mutation and TNT only**. It never blocks commands, so operators
(and console/RCON, which is level 4) can always run `/golf course landscape unlock`. That
is the intended emergency escape hatch and there is no downside to allowing it.

## Protected Surfaces

1. **Break** - reuse the existing `PlayerBlockBreakEvents.BEFORE` guard, extended to the
   new verdict logic.
2. **Place** - Fabric API has no block-place event, but `BlockEvents.USE_ITEM_ON`
   (`(ItemStack, BlockState, Level, BlockPos, Player, InteractionHand, BlockHitResult)
   -> InteractionResult`) fires on item-on-block. The guard denies the placement when the
   clicked position or the adjacent placement position is protected.

   **Implementation note (S2, verified against Fabric API 0.160.0+26.2 and Minecraft
   26.2):** the callback must return `null` to let vanilla run, and
   `InteractionResult.CONSUME` to deny. `InteractionResult.FAIL` does *not* cancel the
   placement: the mixin only substitutes the `BlockState#useItemOn` return value, and
   `ServerPlayerGameMode#useItemOn` checks `consumesAction()` (`false` for `FAIL`), then
   falls through to `ItemStack#useOn`, which places the block. `CONSUME` has
   `consumesAction() == true`, so the placement is skipped. Denial is limited to held
   `BlockItem`s (and TNT in S3) so ordinary interactions such as doors and buttons keep
   working inside a perimeter.
3. **TNT detonation** - see below.

## TNT Protection (no Mixin)

Fabric API provides no explosion event, and the milestone deliberately avoids Mixins.
Instead of guarding the blast, M8.10 guards TNT at every point it can enter the world,
using only public events. This is scoped to protected course areas; TNT outside a
perimeter is unaffected.

1. **Deny placing TNT** - `BlockEvents.USE_ITEM_ON` returns `FAIL` when the held item is
   TNT (or a TNT minecart) and the target position is within the perimeter expanded by a
   small blast safety margin.
2. **Deny direct ignition** - the same event returns `FAIL` when the clicked block is TNT
   and the held item ignites it (flint & steel, fire charge) inside the zone.
3. **Cancel the spawn (catch-all)** - igniting TNT adds a `PrimedTnt` entity, so
   `ServerEntityEvents.ALLOW_LOAD` returning `false` for a `PrimedTnt` inside the zone
   means it never exists and never explodes. This covers what the item-level checks
   cannot: TNT placed before the perimeter was authored, redstone/dispenser ignition,
   fire, and flaming arrows.

   Signature: `boolean onAllowLoad(Entity, ServerLevel, EntitySpawnReason, boolean
   loadedFromDisk)`. The guard cancels only new spawns (`!loadedFromDisk`) so chunk-loads
   of saved entities are never silently deleted.

The perimeter is expanded by a named blast safety-margin constant when evaluating TNT, so
a charge placed just outside the boundary that would still reach protected blocks is also
caught.

## Commands

All gamemaster-gated, and all target the player's current course:

```text
/golf course landscape bounds    # two-corner capture, like /golf hole bounds
/golf course landscape clear     # remove the perimeter and unlock
/golf course landscape lock      # DENY_ALL inside the perimeter (operators included)
/golf course landscape unlock    # operators exempt inside the perimeter again
/golf course landscape status    # bounds corners, dimension, lock state, draft|finalized
```

`clear`, `lock`, `unlock`, and `status` also accept an optional explicit `[<id>]`
(implementation note, S4): the lock must never be able to strand a course, so
console/RCON (level 4, no player) can always run
`/golf course landscape unlock <id>` as the documented escape hatch. `bounds` stays
player-position based.

Target resolution and the "select a course first" requirement:

1. If the player has a current draft (`/golf course edit <id>`), target it.
2. Otherwise, target the active selected course (`/golf course select <id>`).
3. Otherwise fail with `[golf] no course selected; use /golf course select <id> or
   /golf course edit <id>`.

`lock`/`unlock` require an existing perimeter (otherwise tell the operator to set bounds
first). `bounds` uses a per-player pending landscape corner, mirroring the existing
`PendingCorner` flow, and refuses to mutate while a round/attempt is active.

## Persistence

- Extend the authored-course world JSON with per-course landscape metadata; missing fields
  load as "no perimeter, unlocked".
- `clone` copies landscape metadata; `delete` removes it.
- No network payload changes: protection is server-only, so no payload version bump.

## Bounded Slices

Each slice must pass its verification before the next begins. Stop and document any
required deviation from `docs/ARCHITECTURE.md`.

### S0 - Region and Verdict Model

- Add the landscape region type and a pure `ALLOW` / `DENY_NON_OP` / `DENY_ALL` verdict,
  combining tee/cup cylinders and the landscape box with most-restrictive-wins.
- Plain-Java tests: inside/outside, locked vs unlocked, operator vs non-operator, and a
  position inside both a cylinder and a locked box.

### S1 - Course Landscape Store and Persistence

- Add `CourseLandscape` and store it per course (draft and finalized); handle clone,
  delete, and default-course interactions.
- Extend world JSON load/save with backward-compatible defaults.
- Tests: round-trip, missing-field defaults, clone/delete, draft and finalized.

### S2 - Break and Place Guard

- Extend `CourseBlockBreakGuard` to the verdict model and index landscape regions for
  both drafts and finalized courses.
- Register `BlockEvents.USE_ITEM_ON` and deny protected placements.
- Verify no regression to non-protected terrain, and that operators remain exempt when
  unlocked.

### S3 - TNT Guard

- Deny TNT placement and direct ignition inside the perimeter (plus blast margin) via
  `BlockEvents.USE_ITEM_ON`.
- Register `ServerEntityEvents.ALLOW_LOAD` to cancel newly spawned `PrimedTnt` inside the
  zone, and confirm no Mixin or mixin config is added.
- Verify TNT ignites normally outside the perimeter, is refused inside it, is refused
  when placed just outside so its blast would reach in, and that operators are also
  refused — except when unlocked, where operators regain TNT (via the lock semantics).

### S4 - Commands and Feedback

- Add `/golf course landscape bounds|clear|lock|unlock|status` with the target-resolution
  and "select a course first" behavior.
- Verify operator feedback for missing perimeter, missing selection, and active play.

### S5 - Integrated Verification and Closeout

- Verify as operator and non-operator, on draft and finalized courses, that break/place/
  TNT are denied inside and allowed outside; that `unlock` restores operator repair; that
  protection survives a restart; that console/RCON can unlock; and that normal golf play
  (including ball recovery) is unaffected.
- Record results in `docs/M8.10-CLOSEOUT.md`.

## Non-Goals

- Protecting entities, drops, or players from explosion damage.
- Non-TNT explosions: beds, respawn anchors, end crystals, fireballs, wither skulls, and
  creepers (may be reconsidered later; the Peaceful/Creative profile makes them unlikely).
- Fire spread, pistons, endermen, or other non-break/non-place/non-TNT vectors.
- Blocking TNT outside protected course perimeters; TNT remains a normal item elsewhere.
- Removing TNT from the creative inventory (not possible server-side without a Mixin or
  resource pack; M8.10 blocks its use inside protected zones instead).
- Per-hole or per-region granularity beyond the single course perimeter.
- Changing finalize semantics for hole metadata; only landscape metadata stays mutable.
- Client-side presentation, HUD, or network payload changes.

## Exit Criteria

M8.10 is complete when:

1. A course perimeter can be authored on a draft or a finalized course and persists.
2. Non-operators cannot break or place blocks inside the perimeter.
3. TNT cannot detonate inside the perimeter (its `PrimedTnt` spawn is cancelled), while
   TNT still works normally outside it.
4. `landscape lock` blocks block mutation and TNT for operators too; `unlock` restores
   operator repair.
5. Operators can edit outside the perimeter and inside an unlocked perimeter.
6. Commands operate on the selected course and prompt to select one when none exists.
7. Existing tee/cup protection, golf play, ball recovery, and persistence still work.
8. Automated, Loom, Docker, installed-client, and manual verification pass, and
   `docs/M8.10-CLOSEOUT.md` records results. No Mixin is introduced.
